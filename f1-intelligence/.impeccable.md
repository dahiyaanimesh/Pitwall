# PITWALL — Design Context

> **Impeccable design guidance for Claude Code.**
> Read this before any UI work on the PITWALL F1 intelligence dashboard.

---

## Design Context

### Users

Technical recruiters and F1-literate users evaluating the project as a portfolio piece. They are analytically minded — they notice when data is sloppy, when visual hierarchy breaks down, or when something looks templated. They open this expecting to be impressed. The "wow factor" is a hard requirement, not a nice-to-have. Every design decision should pass the test: *does this look like something a real sports analytics team at a well-funded startup would ship?*

### Brand Personality

**Precision · Authoritative · Cinematic**

The register is F1 TV Pro meets Bloomberg terminal — serious, data-dense, visually taut. Not playful, not corporate, never decorative. Every element earns its place through information value. The interface should feel like a professional tool that happens to look extraordinary, not a design exercise that incidentally shows data.

Three-word filter for every design decision: *Would a real pitwall engineer trust this?*

### Aesthetic Direction

**Tone**: Dark, near-black surfaces with maximum contrast reserved for data that matters. Tension comes from restraint — the red accent (`#E10600`) hits harder because everything around it is almost black.

**References**:
- F1 TV Pro — telemetry layouts, tight typography, team color coding
- Linear.app — disciplined spacing, typographic hierarchy, deliberate emptiness
- Bloomberg terminal — information density without chaos, monospace data presentation

**Anti-references** (never produce these):
- Generic Bootstrap/MUI dashboards with default blue accents
- Tableau-style charts with thick borders and colored backgrounds
- Rounded-everything, pastel, gradient-heavy "SaaS dashboard" aesthetics
- Free admin templates (Metronic, AdminLTE, etc.)
- Any layout that could belong to a university data viz course

**Theme**: Dark mode only. Background `#0a0a0a`, card surfaces `#111111`–`#141414`, borders barely visible (`#1f1f1f`–`#2a2a2a`). F1 red `#E10600` is the sole accent — use it sparingly so it retains authority.

### Typography Rules

| Role | Font | Usage |
|---|---|---|
| Display / hero stats | `Rajdhani` | Large position numbers, championship points, big callout values |
| Body / UI text | `Inter` (fallback `Outfit`) | Labels, descriptions, table cells, nav |
| Data / numbers | `JetBrains Mono` | Lap times, deltas, percentages, any numeric readout |

- **Section labels**: 10–11px, `font-weight: 600`, `text-transform: uppercase`, `letter-spacing: 0.12–0.18em`, color `#6b7280`
- **Headlines**: uppercase, tight tracking (`0.06–0.1em`), white or near-white
- **Data values**: always monospace; never round numbers in display contexts — precision is the brand

### Design Principles

1. **Every number must feel like it matters.**
   Data is the product. Never clip, abbreviate, or deprioritize a data point for layout convenience. If a number has to go, the layout should be redesigned instead.

2. **Earn the accent.**
   F1 red (`#E10600`) is reserved for the most important element on screen — active state, P1, critical callout. If it appears more than 2–3 times in a viewport, something has been promoted that shouldn't be.

3. **Restraint creates tension.**
   Empty space isn't wasted space — it creates visual weight around data. Resist the urge to fill. Thin borders, subdued backgrounds, and generous padding between sections make the data feel authoritative.

4. **Precision over decoration.**
   No gradients for their own sake. No shadows that don't ground an element. No border-radius inflation. The existing `8px` card radius is the maximum — go tighter when in doubt. Animations should be purposeful (bar fills communicating magnitude, fade-ins communicating load sequence) not cosmetic.

5. **Information hierarchy must be readable at speed.**
   A user scanning during a live race weekend should be able to extract the critical number within 1 second. P1 driver, points gap, fastest lap — these must win the hierarchy competition on every page.


Team colors are canonical — always use the defined token when identifying a constructor. Never substitute a generic color for a team that has a defined token.

## What "Premium" Looks Like Here

- Tables: no visible row backgrounds except on hover (`rgba(255,255,255,0.02)`); borders only `#161616`
- Charts: no chart background fill, axis lines muted or absent, grid lines `#1a1a1a` dashed
- Cards: no box-shadow by default; shadow only when card is elevated/active
- Badges: 9–10px, uppercase, tight tracking, color-matched bg at 10–12% opacity with 30% border
- Loading: skeleton shimmer (`#1f1f1f` → `#2a2a2a`) not spinners, unless full-page
- Iconography: Lucide icons at 12–15px; never decorative, always paired with a label or clear context
- Spacing: 4px base unit; card padding `24px`; section gaps `16px`; never pad down to `8px` except intra-component
